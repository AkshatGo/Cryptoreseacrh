Method · cost model & provenance

What the numbers mean.

The simulator is a transparent cost model built on the same pipeline the benchmark harness measures. Every displayed byte and timestamp comes from a formula or a recorded sample — nothing is hidden.

01

Handshake

The gateway runs KEM key generation and publishes its public key. The device encapsulates a shared secret and opens an AES-256-GCM channel. The session footprint is the KEM public key + ciphertext + the device signature public key.

setup B = kem.pk + kem.ct + sig.pk
02

Transaction

Each 100-byte reading is signed by the device and encrypted. The gateway verifies the signature and acknowledges. Closed-loop throughput is therefore dominated by one sign, one verify, the AEAD work and the local round trip.

tx B = 100 + 2 + sig B t/tx = sign + verify + 0.27 ms overhead
03

Block seal

Every N transactions, the gateway computes a Merkle root over the pooled transactions, builds an 84-byte header and seals the header hash with its own signature. There is no proof-of-work: this is authority-style sealing, as lightweight IoT chains use.

block B = 84 + 2 + seal + N × tx B
04

Validation

A full chain walk checks every hash link, every Merkle root, every block seal and every transaction signature. The tamper test flips one payload byte and confirms the chain is rejected.

verify all = Σ (tx sigs) + Σ (seals)

Reference profile & honesty notes

simulated
  • Post-quantum values are a reference profile. This checkout contains only the ECDH/ECDSA raw results, so ML-KEM, ML-DSA, Falcon and SLH-DSA figures are representative liboqs/x86-64 numbers used to drive the simulation. They are not measured on this device.
  • Playback is not wall-clock accurate. The animation is compressed so a run stays watchable. The statistics panel reports the model's simulated timings, which preserve the relative cost of each algorithm.
  • Not modeled: network latency beyond a fixed 0.27 ms local round trip, peak memory, scheduler noise, and proof-of-work. The harness itself runs real TCP over loopback and real crypto; this page does not.
  • Each scheme self-tests before timing. The harness requires a KEM round trip to agree and rejects a tampered message before recording any sample. That discipline is reflected in the simulated pipeline: a bad signature never enters the block pool.
  • Signature sizes matter twice. A post-quantum signature is paid on every transaction and again in the block seal. The block signature-share metric makes that cost visible.
